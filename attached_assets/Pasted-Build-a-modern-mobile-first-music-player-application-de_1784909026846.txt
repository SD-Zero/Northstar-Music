Build a modern mobile-first music player application designed primarily for devices such as iPads and tablets. The application should function completely offline and store everything directly on the device's local storage. There should be no accounts, subscriptions, cloud storage, external servers, or online databases. All songs, album artwork, playlists, settings, and user data should remain private and stored only on the user's device.
The application should have a premium, professional music player appearance with a design optimized for touch screens. The interface should feel like a real commercial music app, with smooth animations, large touch-friendly controls, clean spacing, rounded corners, and a visually immersive experience. The app should prioritize a beautiful user experience rather than feeling like a basic file browser.

The main screen should be focused on the currently playing song. In the center of the screen there should be a large album cover that acts as the main visual element. The album artwork should be displayed prominently and should smoothly animate whenever the currently playing song changes. Under the album cover should be the song title and artist name. Beneath the song information should be a playback progress bar that displays the current playback position and the total length of the song. The user should be able to touch and drag the progress bar to move to any point in the song.

Below the progress bar should be the main playback controls. These should include previous song, play/pause, and next song buttons. The buttons should be large enough to easily press with fingers on a tablet screen. Additional controls should include shuffle, repeat, and volume controls. The interface should clearly show when shuffle or repeat modes are active.

The main player screen should have a unique visual carousel effect. To the left and right of the main album cover, the application should display the previous and next songs in the current queue. These album covers should be smaller, slightly faded, and tilted in opposite directions to create a layered 3D appearance. They should appear partially behind the main album artwork. If there is no previous song or next song available, that side should remain empty rather than showing a placeholder. When changing songs, the album covers should smoothly animate between positions, creating a polished transition where the next song moves into the center and becomes the primary artwork.

The background of the player screen should optionally adapt to the current album artwork. The application can extract colors from the album cover and create a blurred, dynamic background that smoothly changes whenever a new song starts. The overall effect should make the currently playing song feel visually unique and immersive.

The music library should not constantly take up space on the main screen. Instead, there should be a hidden library panel accessible from the side of the screen. A small arrow button or swipe area should be placed along the edge of the display. When the user taps the arrow or swipes from the edge, the library panel should smoothly slide into view. When closed, the main player should return to full-screen focus. The panel should be designed specifically for tablet screens and should allow easy touch navigation.

Inside the library panel, the top section should contain playlist tabs. These tabs should be horizontally scrollable using touch gestures, allowing the user to create as many playlists as they want without the interface becoming crowded. Each tab should represent a playlist created by the user, and the currently selected playlist should have a clear visual indicator.

Below the playlist tabs should be an Edit Mode button. When Edit Mode is turned off, the library should focus on normal browsing and playback. When Edit Mode is enabled, playlist and song management controls should become available.

While Edit Mode is active, a plus button should appear next to the playlist tabs. Pressing this button should allow the user to create a new playlist. The user should be able to enter the playlist name using the device keyboard, and the new playlist should immediately appear in the scrollable playlist section.

When Edit Mode is active, every playlist tab should also have a delete option. Pressing the delete option should display a confirmation message before removing the playlist. Removing a playlist should only remove the playlist itself and should not delete the actual music files stored on the device unless the user specifically chooses to permanently remove those songs.

Edit Mode should also allow the user to manage songs inside playlists. Songs should be rearrangeable through touch-based drag and drop. The user should be able to press and hold a song, move it to a different position, and release it to reorder the playlist. The new order should automatically save and remain the same after closing and reopening the application. Songs should also have options to remove them from a playlist, edit their information, or remove them completely from the local music library.

The application should have a simple song importing system. The user should be able to press an Add Song button and choose an MP3 file from the device's file picker. After selecting the file, the application should ask the user to enter the song title, artist name, and select an album cover image. The user should then be able to choose which playlists the song belongs to. After confirming, the application should copy the song into its own local storage system, save the metadata, and immediately make the song available in the library.

The application should maintain a local database that stores all information required for the music library, including song names, artists, album artwork locations, audio file locations, song duration, play history, play count, favorites, playlist memberships, and custom playlist ordering. The database should be stored only on the device.

The app should support unlimited playlists and songs depending only on the available storage space of the device. It should include fast searching through the local library, allowing the user to search for songs, artists, or playlists instantly. The user should also be able to sort and organize music based on different criteria such as recently added, recently played, favorites, artist, and song title.

The application should include mobile-specific interactions such as swipe gestures, touch-based dragging, smooth scrolling, tablet-friendly layouts, support for different screen sizes, and optimized performance for devices with touch displays. The interface should work naturally with fingers rather than requiring mouse or keyboard interaction.

The application should remember the user's preferences and state between launches. It should remember the last played song, current playlist, playback settings, shuffle and repeat states, theme preferences, and library panel position. When reopening the app, it should feel like the user never left.

The code should be structured cleanly with separate systems for audio playback, local file management, database storage, playlists, importing music, user settings, interface components, and animations. The goal is to create a fully functional personal music player application that feels like a professionally designed streaming app while being completely private, offline, and controlled entirely by the user on their own device
